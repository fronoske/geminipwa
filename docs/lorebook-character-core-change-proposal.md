# 会話の中で人物コア設定が変化した場合に会話履歴とlorebook-referenceとで矛盾が起きる問題に対処する仕様案

状態: **検討案・未実装**。以下は将来の仕様を決めるための記録であり、現在のアプリの動作を記述する要件ではない。

## 問題と例

選択された人物コアは、保存済みの `characters[].core` から毎回 `<lorebook-reference>` に組み込まれる（`src/lorebook.ts` の `selectContext` と `buildPrompt`）。会話の進行だけで保存済みの人物コアを書き換える処理はない。

例えば主人公のコアが「黒髪ボブ」で、会話中に散髪してショートカットになった場合、次の送信には「ショートカットになった」という会話履歴と「黒髪ボブ」という人物コアが併存し得る。LLMが時系列に沿って解釈できる場合もあるが、基礎設定と確定した変化の優先関係が明示されていないため、古い髪型で描写する可能性がある。

目標は、会話で確定した変化を現在の描写に反映しながら、変化していない設定を人物コアから引き続き使えるようにすること。この例では、髪型はショートカット、髪色は黒のままとする。共有のLorebookを編集するだけで、別の会話の主人公まで同じ髪型に変えてしまう扱いは避けたい。

## 案1: 送信時の解釈指示を追加する

`src/lorebook.ts` の `buildPrompt` が組み立てる `<lorebook-reference>` に、次の趣旨の指示を加える案。

> 人物コアは基礎設定として参照する。会話の中で明確に成立した変更があれば、変更された項目についてはその場面の現在状態を優先する。変更されていない項目には人物コアを適用する。仮定、予定、夢、過去の回想だけで現在状態を変更しない。

最小の変更で試せるが、変化が実際に成立したか、現在の場面がいつかという判断はLLMに依存する。会話が長くなり、変化の根拠が送信される文脈から失われた場合、この指示だけでは現在状態を復元できない。人物コアが「常に変わらない設定」と「物語中に変わり得る状態」を一つの文章に混在させている場合の解釈も残る。

## 案2: セッションの現在状態を別に保持する

共有のLorebookに基礎設定を置き、その会話で確定した変化をセッションごとの現在状態として保持する案。概念上は、人物ID、変更した項目、現在値、変更の根拠となる会話箇所を関連付ける。例: `主人公 / 髪型 / ショートカット / 散髪が確定した発言`。人物コア全体を置き換えず、項目ごとに現在値を適用する。

送信時には、関連する人物コアと現在状態を同じ `<lorebook-reference>` へ入れ、同一項目では現在状態を優先する。応答ごとの送信情報には、その時点で実際に送った参照文を記録する。過去の応答の表示を、後から変わった現在状態で書き換えない。

状態の登録方法は未決定。手動で追加・訂正できる仕組みと、会話から変更を自動抽出する仕組みを比較する。自動抽出を選ぶ場合は、確定した出来事と仮定・予定・回想・LLMの誤描写を区別し、誤抽出を利用者が訂正できるようにする必要がある。抽出に追加のLLM処理を用いる場合の費用と待ち時間も評価する。

`src/message-sending.ts` では再生成時に送信対象の会話を途中までに切り、通常送信では現在の会話を使用する。分岐した応答のうちAPIへ渡すのは選択中の応答である。現在状態を実装する際は、この**実際に使う会話経路**に基づいて構築する。再生成、分岐の切り替え、会話履歴の編集・削除後に、採用されなくなった経路の変化が残らないようにする。保存・読み込み・複製・JSON出力/取込でも、経路と状態の対応を保つ。

## 決めるべき点

- 最初に案1だけを試すか、セッションの現在状態も併せて実装するか。
- 人物コア内の変更可能な状態をどう見分けるか。元の文章を維持して項目単位で上書きするか、構造化された項目を導入するか。
- 現在状態を手動で管理するか自動抽出するか。自動抽出する場合の確認・訂正方法と処理タイミング。
- 同じ項目が再度変化した場合や、回想・時系列の前後がある場合に、どの出来事を現在値とするか。
- 現在状態を送信する際の選択条件、文字数上限、人物コアと現在状態のどちらかだけが省略されないための扱い。
- 会話の分岐、再生成、編集・削除で状態を再計算する方法と、保存形式の変更・移行方法。
- 全文ソースを送る初期のユーザー発言でも、後の会話で確定した変化との優先関係をどう表すか。

## 採用後の確認例

1. 「黒髪ボブ」の主人公が散髪した後の応答では「黒髪ショートカット」と描写し、変化していない設定を保つ。
2. 「ショートカットにしたらどうなるだろう」という仮定や、過去の写真の描写だけでは現在の髪型を変えない。
3. 散髪を含む応答の再生成、別の分岐の選択、履歴の編集・削除に応じて現在状態が変わる。
4. 同じLorebookを使う別のセッションには、このセッションだけの散髪を反映しない。
5. 保存・読み込み・出力/取込後も、各応答の送信情報が当時の `<lorebook-reference>` を示す。
