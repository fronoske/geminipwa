# 実装要件

## 設定画面のチェックボックス

- 共通システムプロンプトを含む設定項目のチェックボックスは、説明文が長く折り返す場合も一定の大きさを維持する。

## OpenRouter モデル一覧

- モデル ID が `:batch` で終わる Batch 版は取得時と保存済みカタログの復元時に候補から除外する。表示名に含まれる単語では判定しない。既存の Batch 版の選択も読み込み時と次の取得成功時に除外する。
- OpenRouter の手動追加モデル欄と手動追加モデルの選択グループを廃止する。既存の手動追加設定は読み込まず、モデル選択肢にはチェック済みモデルだけを表示する。以前の選択モデルが候補から外れた場合は残る候補へ切り替える。
- 提供元フィルタに Mistral、Moonshot、Meta、Stealth を追加する。Mistral は `mistralai`、Moonshot は `moonshotai`、Meta は `meta` と `meta-llama`、Stealth は `stealth` のモデル ID を分類する。表示名の「AI」は省略する。
- モデル ID の提供元部分が `~openai` など先頭に `~` を1文字含む場合は、分類時だけその文字を除き、既知の提供元へ分類する。送信・保存するモデル ID は変更しない。保存済みカタログも読み込み時に再分類する。
- OpenRouter の最新モデル一覧の取得に成功したとき、API の応答に ID が存在しない選択済みモデルを自動で解除し、保存する。取得失敗時と保存済み一覧の読み込み時は自動解除しない。アプリ側の表示条件で一覧から外れたモデルは解除しない。
- モデル一覧に検索欄を設け、入力するたびにモデル名またはモデル ID を大文字・小文字を区別せず絞り込む。提供元フィルタおよび「表示中を選択／解除」と併用できること。

## メッセージ編集と履歴

- セッション画面で入力・出力を編集して保存すると、その内容を履歴データへ保存する。保存直後に履歴一覧を開いた場合も、保存完了後のデータを表示する。
- 最初の入力から自動生成された履歴タイトルは、その入力の編集後に更新する。履歴一覧で明示的に変更したタイトルは維持する。

## 履歴一覧の操作

- ヘッダーには履歴タイトル、ハンバーガーメニュー、チャットへ戻るボタンを表示する。
- 履歴メニューは「新規チャット」「JSON取込」「一括JSON取込」「一括JSON出力」、区切り線、赤字の「全削除」の順に表示する。チャット画面のハンバーガーメニューには「新規チャット」を表示しない。
- 既存の一括操作の表示設定は、メニュー内の一括JSON取込・一括JSON出力に適用する。新規チャット、JSON取込、全削除は常に利用できる。
- 履歴一覧の各行に「出力」（ツールチップは「JSON出力」）を設け、単体のセッションをJSONオブジェクトとして保存する。JSON取込はこの形式のファイルを1件の別履歴として追加する。入出力する項目と復元方法は一括JSONと共通にする。
- 履歴メニューの「新規チャット」は通常時に追加確認せず開始する。応答中、編集中、添付準備中、保存失敗時の確認と開始前の保存は維持する。
- メニューは操作選択、外側のクリック、Escape、フォーカス離脱、画面切替で閉じる。矢印キー・Home・Endによる項目移動に対応する。
- 操作メニューは履歴一覧の本文より前面に表示し、各項目を表示・クリックできること。履歴の有無や画面幅にかかわらず本文に覆われない。
- 全削除では削除対象の件数と取り消し不可を確認する。キャンセル時はデータを変更しない。設定と登録済みLorebookは保持する。
- 削除前に進行中のメッセージ編集保存を待ち、削除のトランザクション完了後に現在のセッションと編集状態を新規状態へ戻し、リロードせず空の一覧を表示する。削除失敗時は現在のセッションを維持する。
- 応答中の全削除は実行せず、応答を停止してから実行する案内を表示する。全削除の重複実行を防ぐ。

## Google Analytics

- GitHub Pages 用の `index.html` には GA4 測定 ID `G-LYK4N70WLR` を設定し、Google タグでページビューを計測する。
- `GA_MEASUREMENT_ID` 環境変数でビルド時の測定 ID を変更できるようにする。
- チャット名を含む動的なページタイトルと URL のクエリ文字列を Analytics へ送らない。
- `GA_MEASUREMENT_ID` に空文字列を指定したビルドでは Google タグを含めない。
- Service Worker のキャッシュを更新し、既存の PWA インストールにも新しい公開用 HTML を届ける。

## 公開ビルドと PWA インストール

- 公開用 HTML は非公開の `lorebook.local.js` を読み込まない。開発サーバーでは従来どおり読み込めるようにする。
- PWA のインストール案内をブラウザが表示できるようにし、表示を抑止する `beforeinstallprompt` ハンドラーを置かない。

## Lorebook の動的情報上限

- 設定画面の Lorebook 管理ボタンは「新規」「JSON取込」「JSON一括出力」とする。JSON取込は単体・複数件の Lorebook を受け付け、JSON一括出力は登録済みの全件を一つのファイルに出力する。
- Lorebook の各行は個別出力ボタンを「JSON出力」と表示し、「編集」の後、「削除」の前に配置する。個別出力は従来どおり対象 Lorebook 1件を JSON 形式で保存する。
- 「新規Lorebookを追加」画面で、呼称ルール・人物コア・条件付き記憶に共通する文字数上限 `retrieval.maxDynamicCharacters` を指定できるようにする。初期値は12,000文字とし、`DEFAULT_LOREBOOK_RETRIEVAL.maxDynamicCharacters` から表示する。
- 1以上の整数だけを受け付け、解析結果の確認を経て保存した Lorebook に入力値を保持する。
- 既存 Lorebook の編集画面では現在の上限値を表示し、変更して保存できるようにする。既存の保存値はユーザーが変更するまで維持する。

## 初回ユーザープロンプト

- 設定画面の Lorebook セクションの直後に「初回ユーザープロンプト」セクションを設ける。「新規」「JSON取込」「JSON一括出力」を表示する。
- 「新規」は専用の編集画面を開く。画面の基本配置は「新規Lorebookを追加」と揃え、編集領域にはタイトルのテキスト入力欄、本文のラベルとテキストエリア、「保存」ボタンだけを置く。タイトルと本文は空白だけでは保存できない。
- 保存済みの各項目はタイトルと「編集」ボタンを一覧表示する。「編集」は新規作成と同じ画面を保存内容入りで開き、保存時にその項目を更新する。
- 保存済みの各項目は「編集」の横に「削除」ボタンを表示する。削除前に確認し、取り消した場合は変更しない。削除後は一覧を更新し、未送信のチャットで選択中だった場合は選択とプレビューを解除する。既存チャットに保存済みの適用スナップショットは保持する。
- 初回ユーザープロンプトの各行は「編集」「JSON出力」「削除」の順に配置する。個別の「JSON出力」は対象1件を、一括出力と同じ JSON 形式の `prompts` 配列に入れて保存し、既存の JSON 取込で読み込めるようにする。
- 初回ユーザープロンプトは Lorebook と区別してブラウザ内に永続保存する。各項目に安定した ID、タイトル、本文、作成日時、更新日時を保持する。
- 「JSON一括出力」は全件を `{ "format": "GeminiPWA Initial Prompts", "version": 1, "prompts": [...] }` 形式の一つの JSON ファイルに出力し、「JSON取込」は同形式の全件を検証して取り込む。不正なデータがあれば一件も変更しない。同一 ID が既にある場合は上書き前に確認する。
- チャット画面のハンバーガーメニューで Lorebook の直後に「初回プロンプト」を置く。保存済み項目または「使用しない」を選択でき、選択中のタイトルをメニューに表示する。選択できるのはその会話の初回送信前までとし、新規チャットでは未選択に戻す。
- チャット画面のメニューに表示する Lorebook と初回プロンプトのタイトルは、長い場合も折り返して全文を表示する。メニューは画面の左右からはみ出さないように配置し、縦に収まらない場合はスクロールできるようにする。
- 初回プロンプトの選択は、それだけでは API 呼び出しを行わない。会話の最初の送信時に選択本文を手入力本文より前に一度だけ適用し、再送や以後の送信で重複適用しない。適用時の本文はスナップショットとして会話に保持し、後から登録内容を編集しても過去の会話は変わらない。
- API へ送る際は初回プロンプト本文と手入力本文を一つの `user` ターン内で順序を保って渡す。送信テキストは `【初回プロンプト：タイトル】`、初回プロンプト本文、`【ユーザー入力】`、手入力本文の順とする。会話画面では両者の出所を区別できるようにする。これにより、連続する `user` ターンの扱いが API ごとに異なっても同じ結果を得られるようにする。
- 初回プロンプトを選択したときは、チャット画面に未送信と分かるユーザー吹き出しとして表示する。最初の入力を送信した後は、適用した初回プロンプトのスナップショットを独立したユーザー吹き出しとして手入力の直前に表示する。本文は初期状態で折りたたみ、タイトルから展開できる。表示用の吹き出しは送信・保存するメッセージ件数に加えない。

## チャット入力

- 入力が空で添付ファイルもなく「送」ボタンが非アクティブの場合、そのボタン領域をタップするとチャットを最下部までスクロールする。
- 非アクティブな「送」ボタン以外の入力欄、貼り付けボタン、フッター領域の既存操作には影響させない。

## 入力プリセット

- 入力プリセットツールバーは、設定画面の「入力プリセット」にある「常に表示」が未選択の場合、入力欄が空または空白文字だけの状態でフォーカスされたときに表示する。
- 「常に表示」が選択されている場合、入力欄の内容にかかわらず、入力欄がフォーカスされたときにツールバーを表示する。この設定は保存し、次回起動時にも復元する。
- プリセット本文にカーソル位置指定 (`{|}`) がない場合、プリセット文字列を入力済みテキスト全体の直後へ追加する。
- プリセット本文にカーソル位置指定 (`{|}`) がある場合、マーカーを除いたプリセット文字列を入力欄へ配置し、入力済みテキスト全体をマーカー位置へ移動する。処理後のカーソルは、移動した入力済みテキストの直後に置く。

## 検索・置換

- メイン画面のハンバーガーメニューに「検索・置換」を追加する。
- メニュー選択時に、検索ワード、置換ワード、検索対象（全体／編集中の応答）、置換方法（一括置換／逐次置換）、OK、Cancel を備えたダイアログを表示する。
- 検索は大文字・小文字を区別するリテラル検索とし、空の検索ワードは受け付けない。
- 対象となるテキストは、現在表示しているセッションのメッセージ本文 (`currentMessages[].content`) とする。カスケード応答は選択中の応答だけを対象とし、添付ファイル名、思考要約、チャットタイトル、メモは対象外とする。
- 「編集中の応答」は、既存のメッセージ編集を開始している場合だけ選択できる。検索には編集 textarea の未保存内容を使用する。
- 一括置換は選択した検索対象に含まれる全一致箇所を置換し、チャットを保存してから「n件置換しました」と表示する。n は置換した一致箇所数とする。
- 逐次置換は対象メッセージをセッション先頭から検索し、一致箇所を編集 textarea 上で選択表示する。下部バーに「置換？ Yes / No / All / Cancel」をこの順で表示する。
- 下部バーには現在の一致箇所と全一致数を `n/m` 形式で表示する。m は置換開始時の全一致数、n は現在表示している一致箇所の1始まりの順番とする。
- 一致箇所は専用色でハイライトし、長いメッセージでも一致箇所が画面と編集 textarea の中央付近に来るようにスクロールする。
- 逐次置換および検索モードで一致箇所を表示するために編集 textarea をフォーカスする際は、一時的に読み取り専用かつ `inputmode="none"` とし、モバイル端末のオンスクリーンキーボードを表示しない。処理終了時は通常の編集可能状態へ戻す。
- 逐次置換の `Yes` は現在の一致だけを置換し、`No` は現在の一致を変更せず次へ進み、`All` は現在の一致を含む残りの一致をすべて置換する。`Cancel` は処理を終了し、それまで `Yes` で行った置換は保存する。
- 逐次置換が末尾に達した場合と `all` を選んだ場合は、チャットを保存して「n件置換しました」と表示する。
- 置換後に再検索を続ける位置は挿入した置換ワードの直後とし、置換ワード内を同じ処理で再度置換しない。
- 置換開始前にメッセージを編集中だった場合は、置換処理終了後も同じメッセージの編集表示を復元する。
- 逐次処理中に `Cancel` を選んだ場合は再描画やスクロールを行わず、現在のスクロール位置と、現在一致箇所を表示している回答の編集状態を維持する。
- 置換ワードが空の場合は検索モードとする。検索モードは置換を一切行わず、下部バーを「前へ / 次へ / Cancel」とし、一致箇所間を循環移動できるようにする。進捗表示、中央配置、ハイライト、Cancel時の挙動は逐次置換と共通とする。
